## Statement

The app has a theme system with several distinct themes, including interesting dark and interesting light ones, selectable by the owner in Settings. A theme changes only backgrounds, surfaces and the accent colour. Semantic colour rules are identical in all themes: red = failure, amber = 'decide', AI controls are never filled, and there is one filled accent button per screen. The accent in the quick-post composer is not widened beyond the current rule. A theme may have an animated background, which is optional; it is off by default and is disabled when macOS 'reduce motion' is on. The design system documentation (visual-system.md) is updated to describe themes: it keeps its existing rules and gains per-theme palettes for backgrounds, surfaces and accent.

## Acceptance Criteria

- [x] At least two dark and two light themes with distinct colour character can be selected, and the choice is kept.
- [x] The theme is selected in Settings.
- [x] A theme changes only backgrounds, surfaces and the accent colour; no other colour changes between themes.
- [x] Semantic colour rules are the same in every theme: red = failure, amber = 'decide', AI controls are never filled, one filled accent button per screen.
- [x] The accent colour in the quick-post composer follows the current accent rule and is not widened beyond it in any theme.
- [x] An animated background can be turned off, and the app is fully usable without it.
- [x] The animated background is off by default.
- [x] The animated background is disabled when macOS 'reduce motion' is on.
- [x] Text contrast stays within the design system's measured limits in every theme.
- [x] visual-system.md keeps its existing rules and is updated with per-theme palettes for backgrounds, surfaces and accent.
