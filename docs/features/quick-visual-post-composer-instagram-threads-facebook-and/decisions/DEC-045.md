## Context

The quick-post default picture is a template card drawn by the app (DEC-037, REQ-003). The spec did not say when the card becomes a real image file, where it is stored, or where its headline comes from, since the quick-post composer has no title field. Sending to Instagram, Threads and Facebook needs an actual image file, and the existing pipeline (DEC-030) works with pictures from the per-product library.

## Alternatives

1. Keep only card parameters (text, style, colour, shape) in the draft and render the PNG at send time; the preview is drawn from the same parameters
2. Keep parameters and a cached PNG attached to the draft, re-rendered on every edit, and not added to the library until the owner saves it there
3. Turn the card into an ordinary uploaded picture at once, with no stored parameters; changing it means creating a new card

## Decision

When a quick-post draft is saved, the template card is rendered to a PNG and added to the product's picture library as an ordinary post picture. The card headline is taken from the first line of the caption until the owner edits it separately in the composer. REQ-003 gets an acceptance criterion that saving a draft creates the PNG.

## Reason

The PNG is an ordinary library picture, so approval and sending work unchanged and the pipeline from DEC-030 is not touched. What the owner approves is the exact file that gets sent. It is also the simplest option that still allows changing style and colour by clicks before saving.

## Consequences

Approval and sending need no pipeline changes. The library accumulates card files, and editing a card after saving requires a new render. Style and colour edits by clicks are guaranteed before saving, and re-editing a saved card must be specified in REQ-003 and F-003. The headline-from-first-line rule and the owner's separate headline override need acceptance criteria. This choice shapes the draft storage format, which F-003 still has to settle.
