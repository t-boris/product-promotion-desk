## Context

DEC-030 states that pictures went out only as a Reddit post until a later slice. The quick-post composer (REQ-002) saves drafts that always carry one picture for Instagram, Threads and Facebook. The spec did not state whether the existing sending path can publish a picture post on these platforms, and the approval/publishing pipeline was out of scope. Code hints (the AI browser sending pictures where a connector cannot, DEC-035) only indirectly suggest that it can. If sending is unsupported on a platform, a saved draft could never be published.

## Alternatives

1. Verify in code before implementation and record the result as a fact in REQ-002; requirements change only if a gap is found
2. Accept as an assumption that the AI browser (DEC-035) publishes pictures on these platforms and record it in REQ-002
3. Narrow the platforms: show the quick-post composer only where picture sending is confirmed; the rest stay on the old form (would change DEC-038 and REQ-001)

## Decision

Extend the scope to include work on sending pictures to the platforms among Instagram, Threads and Facebook where it is not yet supported. A separate requirement is added for it, with acceptance criteria per platform. The 'out of scope' boundary on the publishing pipeline is changed accordingly: only the picture-sending part is in scope, while approval flow and the rest of the pipeline stay unchanged.

## Reason

The owner wants quick picture posts on all three platforms, and a draft that cannot be published has no value. Bringing sending into scope removes the risk that this is discovered only after drafts are saved, and avoids both an unverified assumption and a reduced platform set.

## Consequences

Scope and delivery time grow. A new requirement is needed for picture sending, with acceptance criteria for each platform (Instagram, Threads, Facebook). The scope section's 'out' list must be updated, and REQ-002 should link to the new requirement. The first step is to find out per platform whether sending already works, so the work covers only real gaps. DEC-030 and DEC-035 remain valid and are extended, not replaced. DEC-038 and REQ-001 stay unchanged, so the original request is fulfilled completely.
