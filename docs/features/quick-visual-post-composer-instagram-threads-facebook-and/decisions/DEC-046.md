## Context

Existing drafts have a title and Markdown text. A quick post (one picture plus a short caption) has no mandatory title, and F-003 asked how it is stored and how review, approval and preview screens show a draft with no title. DEC-038 derives the post type from the chosen channel, and DEC-045 renders a template card to a PNG on save and adds it to the picture library. The card parameters (style, colour, shape, headline) must be kept somewhere so the card can be re-edited (REQ-003).

## Alternatives

1. Same draft, empty title: the caption goes in the text field, the title stays empty, the picture is an ordinary attachment, and no new field is added. Cheapest, but screens must guess the layout from an empty title and card parameters need separate storage.
2. Post-type field plus an auto-generated title: the title is filled from the first words of the caption and is hidden from the owner. Old screens work unchanged, but it needs a truncation rule and a recompute on every save, and the title can drift from the caption.
3. Decide later at design time: the requirement fixes only behaviour and the storage choice is left to implementation. Shortest spec, but F-003 stays effectively open and screens and storage may diverge.

## Decision

Add an explicit post-type field to the draft with the values article and quick post. For a quick post, the caption is stored in the text field and the title is empty and not required. The template card parameters (style, colour, shape, headline) are kept in a structured field of the draft. Existing drafts get the default type article through a migration. Review, approval and preview screens choose their layout by post type, not by guessing from an empty title.

## Reason

An explicit type lets screens pick the right layout without guessing, and it stays correct if the channel is changed later. Structured card parameters support re-editing a saved card (REQ-003) and the re-render rule from DEC-045. Storing the caption in the text field keeps the approval and sending pipeline unchanged.

## Consequences

A data migration is needed, and the storage layer and every place that reads drafts must be updated. REQ-002 must gain criteria for: the data model with the type field and the default article value for old drafts; a quick post with an empty title shown correctly on review, approval and preview screens, for example by showing the first words of the caption where a label is needed; and the structured card-parameters field. The approval flow stays unchanged. F-003 can be resolved with this decision.
