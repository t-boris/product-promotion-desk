## Context

REQ-005 introduces a theme system (DEC-036), but the existing visual system (visual-system.md) has strict colour rules: one indigo accent used sparingly, one filled button per screen, AI controls never filled, red only for failures, amber for 'decide'. It was not defined whether these rules hold across themes, where the theme is chosen, or whether the animated background respects the system's reduced-motion setting (F-004).

## Alternatives

1. Themes may override everything, including red, amber and accent shades, if contrast stays within limits; the 'one accent' rule becomes only a recommendation.
2. Roles of colours are fixed in all themes, but each theme picks its own shades within contrast limits; the 'one accent' rule is relaxed so the accent may be used more widely in the quick-post composer.
3. Do not fix the rules now; leave F-004 as a note for the design stage and only state in REQ-005 that the theme is chosen in Settings.

## Decision

Semantic colour rules are identical in all themes: red = failure, amber = 'decide', AI controls are never filled, one filled accent button per screen. A theme changes only backgrounds, surfaces and the accent colour. The theme is chosen in Settings. The animated background is off by default and is disabled when macOS 'reduce motion' is on.

## Reason

Fixed semantics keep red, amber and AI controls readable and recognisable in every theme, and keep contrast measurement limited to backgrounds, surfaces and the accent instead of every colour pair. It also leaves the existing design system rules intact while still giving the owner colourful themes.

## Consequences

Add criteria to REQ-005: semantic rules are the same in every theme; the theme is selected in Settings; the animated background is off by default and respects reduced-motion. visual-system.md keeps its rules and gains per-theme palettes for backgrounds, surfaces and accent. Trade-off: less freedom for very bright themes, and the accent in the quick-post composer is not widened beyond the current rule.
