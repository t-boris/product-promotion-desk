## Statement

The system shall keep the passwords of the owner's platform accounts in a vault encrypted with the system keychain and use them to sign the account in on its own browser, handing every check to the owner.

## Acceptance Criteria

- [x] A password can be saved, replaced, removed and shown on request for an account; the account list tells only whether a password is saved.
- [x] A password is never present in the database, log, events, the loopback web API, AI prompts, backups or exports.
- [x] If the system keychain cannot encrypt, the vault says it is unavailable and stores nothing.
- [x] "Sign in with saved password" fills the sign-in form of the account's own browser only on a page of the account's platform and refuses any other site.
- [x] When a login check finds the account signed out, the application signs it in once automatically, at most once per hour per account.
- [x] A CAPTCHA, a second factor or an unexpected page stops the attempt, marks the account as needing the owner and does not retry.
- [x] The application can generate a strong password for a new account.
- [ ] A copied password leaves the clipboard after 30 seconds.
- [x] A sign-in page that draws its form after it has loaded is given up to 15 seconds; the form is looked for again only while it is missing, never after the password was submitted and never after a failed read, so a password is never sent twice.
- [x] Only a human check that a person can see counts as a CAPTCHA: an invisible frame or the reCAPTCHA badge on an ordinary page does not; the log says what showed.
- [x] While the owner's window for an account is open the Accounts screen says so, offers to show the window and to close it, and does not offer actions that need the browser; closing the window gives the browser back, checks the sign-in once and never tries a saved password by itself.
