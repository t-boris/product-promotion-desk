## Statement

Run persistent local background workflows with recoverable progress, visible failures, and user control. Keep automation running after the last window closes; explicit Quit stops automation until manual relaunch.

## Acceptance Criteria

- [ ] Products, accounts, channel configuration, completed analysis stages, pending work, and action history survive application restart.
- [ ] Closing the last application window keeps automation running in the background.
- [ ] Background automation status and pause controls remain accessible while all application windows are closed.
- [ ] Explicit Quit stops all application automation until the user manually launches the application again.
- [ ] After macOS restart or login, the user must launch the application manually; automatic startup at login is outside version 1.
- [ ] No scheduled work runs during sleep, after logout, or while the application is stopped.
- [ ] Workflow progress is persisted on application shutdown.
- [ ] After manual launch, the application rechecks permissions before resuming eligible pending or scheduled work.
- [ ] Scheduled work resumes after sleep or connection loss when the application is running and permissions allow it.
- [ ] Before retrying an uncertain send after any interruption, the application reconciles its outcome and does not blindly repeat it.
- [ ] An expired login or CAPTCHA requests user participation and suspends affected operations.
- [ ] A channel failure does not stop other channels, and an AI-process failure does not close the application.
- [ ] The user can pause automation from every working screen.
- [ ] Each run exposes its time, status, and short result.
