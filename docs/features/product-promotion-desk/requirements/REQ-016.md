## Statement

When an account has an e-mail address and a saved password and the owner asks for it, the system shall have the AI open the account's own browser on the platform's registration page, read the page, fill in every value it considers right, submit the form and, when the site asks a question or refuses something, decide the next step from what it sees on the page; only what a person alone can do (a CAPTCHA, a code sent to a phone) is handed to the owner.

## Acceptance Criteria

- [x] The assistant starts only when the owner presses a button for that account, works only on pages of the account's platform in the account's own browser, and stops at once when the owner takes the browser (REQ-004).
- [x] Before every round the AI is given what the page shows (the usable elements with labels, the text, the messages of the site, a visible human check) and chooses the next step from it; it never repeats an answer without the page having changed (two rounds without a change hand the task to the owner). A screenshot and the requests the page made (DEC-016) are not given to the AI yet.
- [x] The AI answers with steps (type, select, click, key) naming labelled elements and the application carries them out; the AI never holds the browser itself, and a step that names an element that is not on the page, another site, or a password field it was not given is refused (DEC-017).
- [x] The e-mail address and the saved password of the account are typed by the application from the account and the vault; the AI sees a placeholder, and the password never appears in a log, a report, the run state or an AI prompt (DEC-014).
- [ ] The other values (name, birth date, gender, display name, user name) come from the account's role and the product passport, or are proposed by the AI; each value the AI made up is recorded on the account and shown to the owner. (Shown in the run panel now; recorded on the account later.)
- [ ] A refusal by the site that a different value can fix (an e-mail or name that is taken, a weak password, a name the site refuses) is fixed by the AI with a different value, up to a small number of attempts; the same refusal again stops the assistant.
- [ ] A CAPTCHA, a code sent to a phone, a code sent to an e-mail the application cannot read, an identity check or an account the site blocks is handed to the owner with what the AI saw and what it tried, in plain words.
- [x] When the registration is done the application checks the sign-in itself and shows the result; the account does not count as signed in because the AI says so.
