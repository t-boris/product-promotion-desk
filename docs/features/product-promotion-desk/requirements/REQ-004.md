## Statement

Enforce permissions and duplicate prevention at the application boundary for every outgoing publication or reply.

## Acceptance Criteria

- [ ] Approval is bound to the exact text, attachments, account, and destination; changing any of them invalidates approval.
- [ ] Before sending, the application checks account availability, current thread state, existing account replies, permissions, and channel and account limits.
- [ ] An unknown send result blocks another attempt until the previous outcome is resolved.
- [ ] A confirmed send records a destination link or platform identifier, timestamp, and authorization basis.
- [ ] Shared accounts use aggregate limits and cannot receive concurrent control of the same browser session.
- [ ] AI instructions alone cannot authorize outgoing actions; application controls enforce authorization for browser actions as well.
