## Content

**Техническое задание: персональное приложение для продвижения продуктов, версия 1**

Приложение для macOS помогает изучать продукт, находить подходящие сообщества, готовить публикации, отслеживать обсуждения и оценивать результаты продвижения. Для выполнения AI-задач пользователь выбирает установленный Codex или Claude Code.

Первые пользователи — владелец проекта и его друзья. Каждый использует собственную установку со своими данными и аккаунтами. Первый рабочий продукт — Natal Mystic.

Приложение работает на Mac пользователя. Предполагается длительная фоновая работа с восстановлением после перезапуска, сна и потери соединения.

**1. Основные понятия и принципы**

Чтобы настройки оставались понятными, приложение различает следующие объекты:

| Объект | Значение |
|---|---|
| Продукт | То, что пользователь продвигает |
| Площадка | Reddit, Facebook, отдельный форум и другие сайты |
| Аккаунт | Учётная запись пользователя на площадке |
| Канал | Конкретное место работы: сообщество, группа, страница, раздел форума |
| Коннектор | Способ взаимодействия с площадкой |
| Обсуждение | Публикация и связанная с ней переписка |
| Действие | Проверка, подготовка текста, публикация, ответ |
| Кампания | Набор действий с общей целью и периодом проведения |

Один продукт может иметь несколько каналов. Один аккаунт может использоваться в нескольких каналах. Один канал можно связать с несколькими продуктами, но каждое исходящее действие относится к конкретному продукту.

Информация о продукте, история действий и расписания хранятся в приложении независимо от выбранного AI-движка.

AI предлагает решения и вызывает предоставленные инструменты. Разрешения, лимиты, расписания и допустимость отправки контролируются приложением.

**2. Сценарий: добавление продукта**

**Цель пользователя:** объяснить приложению, что нужно продвигать, и получить проверенный паспорт продукта, пригодный для дальнейшей работы.

**Начальные условия:** приложение запущено; выбран и проверен AI-движок. Если движок пока недоступен, пользователь может заполнить данные вручную и продолжить анализ позже.

**Основной сценарий**

1. Пользователь нажимает «Добавить продукт».

   Открывается форма с названием и возможностью добавить:
   - Адрес сайта.
   - Текстовое описание.
   - Документы и изображения.
   - Локальную папку с исходным кодом.

   Достаточно одного источника. Дополнительные материалы можно подключить позже.

2. Приложение показывает, какие материалы будут доступны AI.

   Для папки с исходниками пользователь выбирает область доступа. Секреты, файлы окружения, зависимости и технические каталоги исключаются по умолчанию. Анализ исходников выполняется без запуска кода проекта.

3. AI изучает материалы.

   Пользователь видит этапы работы: чтение сайта, анализ документов, формирование описания, поиск противоречий. Процесс можно остановить и возобновить.

4. Приложение формирует предварительный паспорт продукта.

   | Раздел | Содержание |
   |---|---|
   | Идентичность | Название, адрес сайта, краткое описание |
   | Предложение | Основные возможности и польза |
   | Аудитория | Предполагаемые пользователи и их задачи |
   | Условия | Цены, бесплатные возможности, ограничения |
   | География и языки | Где и на каких языках продвигаем |
   | Коммуникация | Тон, допустимые формулировки, нежелательные обещания |
   | Материалы | Изображения, демонстрации, отзывы, ссылки |
   | Цели | Целевое действие и показатели результата |

   Существенные утверждения содержат источник и дату проверки. Предположения AI отмечаются отдельно.

5. AI задаёт уточняющие вопросы.

   Сначала уточняются сведения, без которых невозможно подготовить корректный текст: официальное название, назначение продукта, актуальные условия и целевое действие.

   Необязательные вопросы можно пропустить. Пропущенные сведения остаются неизвестными.

   Для Natal Mystic, например, нужно уточнить расхождение между названием продукта и названием AstroWeb в публичных метаданных.

6. Пользователь проверяет паспорт.

   Можно исправить текст, подтвердить факт, отклонить предположение или запретить использование конкретного утверждения в публикациях.

7. Пользователь выбирает цель продвижения.

   Например: привлечь посетителей, которые успешно создадут первую натальную карту. Подключение аналитики можно выполнить сейчас или позже.

8. Приложение сохраняет первую утверждённую версию паспорта.

   AI предлагает первоначальные гипотезы аудитории и направления поиска каналов. Для каждой рекомендации показывает основание и сведения, которые ещё требуется проверить.

**Результат:** создан продукт с утверждённой базой знаний, целью и списком первоначальных гипотез продвижения.

**Особые ситуации**

- Сайт недоступен: сохранить продукт и предложить продолжить по описанию или документам.
- Источники противоречат друг другу: показать конфликт, не выбирать версию молча.
- Анализ прерван: сохранить завершённые этапы.
- Возможность найдена только в исходниках: пометить её доступность пользователям как неподтверждённую.
- Неизвестна цена: не включать цену и утверждение о бесплатности в публикации.

**Изменение продукта после создания**

Пользователь может редактировать паспорт и повторно анализировать источники. Новые сведения показываются как изменения для проверки.

Изменение факта, использованного в ожидающем отправки материале, переводит этот материал на повторную проверку. Исторические публикации сохраняются вместе с версией данных, использованной при их создании.

**Критерии приёмки**

- Можно создать продукт по одному адресу сайта или текстовому описанию.
- Подтверждённые факты отделены от предположений.
- Пользователь может исправить паспорт до начала продвижения.
- После перезапуска продукт и результаты анализа сохранены.
- Неизвестные сведения не превращаются в рекламные обещания.
- Смена AI-движка сохраняет паспорт и историю продукта.

**3. Сценарий: подключение нового канала**

**Цель пользователя:** подключить конкретное место продвижения, проверить доступные действия и настроить режим работы.

**Начальные условия:** продукт создан. Канал может быть предложен AI или указан пользователем.

**Основной сценарий**

1. Пользователь выбирает рекомендацию или вводит адрес.

   Поддерживаются команды вида «Подключи этот форум» или «Добавь эту группу». Если указан адрес всей площадки, приложение помогает выбрать конкретный канал.

2. Приложение определяет площадку и доступный коннектор.

   Для известной площадки используется подготовленный коннектор. Для неизвестного сайта запускается обследование универсальным браузерным коннектором.

3. Открывается встроенный браузер.

   Пользователь выбирает существующий браузерный профиль или создаёт новый. Приложение явно показывает выбранный аккаунт.

4. При необходимости пользователь входит на сайт.

   Пароль и дополнительные подтверждения вводятся на странице сайта. AI приостанавливает управление на время входа. Приложение проверяет успешность входа и сохраняет сессию.

   Если аккаунта нет, приложение объясняет порядок регистрации и открывает соответствующую страницу.

5. Коннектор обследует канал.

   Проверяются:
   - Возможность читать публикации и комментарии.
   - Доступные способы обнаруживать изменения.
   - Возможность подготовить и отправить публикацию или ответ.
   - Доступные показатели.
   - Правила сообщества и условия использования автоматизации.
   - Способ проверить результат отправки.

   Обследование не публикует тестовые сообщения в реальном сообществе.

6. Приложение показывает карточку возможностей.

   Каждая возможность получает статус:

   | Статус | Значение |
   |---|---|
   | Проверено | Работа подтверждена в текущем подключении |
   | Требует проверки | Возможность обнаружена, но ещё не подтверждена |
   | Требует участия | На этом этапе нужен пользователь |
   | Недоступно | Коннектор не поддерживает действие |
   | Ограничено правилами | Действие нельзя включить в выбранном режиме |

   Успешное чтение страницы не означает автоматическую готовность публикации.

7. Пользователь настраивает канал.

   Настройки включают:
   - Продукт и аккаунт.
   - Языки и стиль общения.
   - Темы и поисковые запросы.
   - Отслеживаемые обсуждения.
   - Режим обработки комментариев.
   - Частоту проверки.
   - Лимиты исходящих действий.
   - Уведомления и время сводки.

8. Приложение выполняет первый цикл наблюдения.

   Существующие комментарии становятся исходным состоянием. По умолчанию они не считаются новыми событиями для автоответа.

   Пользователь отдельно может выбрать старые обсуждения для обработки.

9. Канал получает статус «Активен».

   Карточка показывает последний успешный запуск, следующую проверку, доступные возможности и проблемы, требующие участия.

**Результат:** канал связан с продуктом, аккаунтом, правилами, расписанием и проверенным набором возможностей.

**Особые ситуации**

- Вход истёк: приостановить действия аккаунта и запросить повторный вход.
- Появилась CAPTCHA: передать управление пользователю.
- Изменилась структура сайта: остановить затронутую операцию и повторно проверить коннектор.
- Страница доступна только для чтения: сохранить канал с соответствующими возможностями.
- Сайт запрещает необходимую автоматизацию: показать ограничение и доступный способ работы.
- Несколько продуктов используют один аккаунт: применять общий лимит аккаунта и исключать одновременное управление одной браузерной сессией.

**Расширяемость первой версии**

Универсальный коннектор может создавать декларативный профиль сайта: адреса, признаки страниц, способы чтения, шаги навигации и проверки результата.

Созданный профиль проходит проверку и получает версию. Самостоятельное выполнение произвольного сгенерированного кода не входит в механизм подключения первой версии.

Подключение нового сайта считается успешным только для фактически проверенных возможностей.

**Критерии приёмки**

- Аккаунт и канал сохраняются после перезапуска.
- Пользователь может забрать управление браузером.
- Агент при этом прекращает взаимодействие с соответствующей вкладкой.
- Показан реальный набор возможностей подключения.
- Первый запуск не вызывает массовые ответы на старые комментарии.
- Ошибка одного канала не останавливает остальные.
- Для каждого запуска доступны время, статус и краткий результат.

**4. Сценарий: обработка комментария**

**Цель пользователя:** получить подходящий ответ на новый комментарий и отправить его в соответствии с настройками канала.

**Начальные условия:** канал активен; обсуждение входит в область наблюдения; настроен режим обработки.

**Основной сценарий**

1. Планировщик запускает проверку.

   Коннектор получает новые данные и сравнивает их с сохранённым состоянием. По возможности используются идентификаторы площадки; при их отсутствии — устойчивое сочетание ссылки, автора, времени и других признаков.

2. Приложение регистрирует новый комментарий.

   Повторно обнаруженный комментарий обновляет существующую запись. Собственные комментарии не запускают цепочку автоответов.

3. Собирается контекст.

   Агент получает:
   - Исходную публикацию.
   - Комментарий и доступную родительскую ветку.
   - Предыдущие ответы аккаунта.
   - Актуальные сведения о продукте.
   - Правила канала и разрешённые действия.

4. AI определяет подходящее действие.

   Возможные категории: вопрос о продукте, благодарность, интерес к покупке, жалоба, критика, нерелевантное сообщение, потенциальный спам.

   Результат может быть одним из следующих: ответить, запросить сведения у пользователя, передать пользователю без черновика, оставить без ответа.

5. При необходимости создаётся черновик.

   Ответ учитывает язык собеседника, контекст разговора и стиль продукта. Ссылки добавляются при уместности и допустимости. Неподтверждённые характеристики, скидки и обещания не используются.

   Вместе с черновиком сохраняются основание ответа и версия знаний о продукте.

6. Приложение применяет режим канала.

   | Режим | Действие |
   |---|---|
   | Наблюдение | Показать событие |
   | Подготовка | Сохранить черновик |
   | С подтверждением | Поместить ответ в очередь согласования |
   | Ограниченный автомат | Проверить все условия автоматической отправки |

   Для первой версии предлагается разрешать автомат только для выбранных простых категорий: благодарности и фактические вопросы, ответ на которые явно присутствует в утверждённой базе знаний.

   Жалобы, индивидуальные скидки, возвраты, спорные обещания и неоднозначные обращения направляются пользователю.

7. Пользователь при необходимости проверяет ответ.

   В карточке видны исходный комментарий, контекст, черновик, аккаунт и место отправки.

   Доступные действия: редактировать, одобрить, отклонить, отложить, открыть в браузере.

   Одобрение относится к конкретному тексту, вложениям, аккаунту и адресу назначения. Изменение этих данных отменяет прежнее одобрение.

8. Перед отправкой выполняется повторная проверка.

   Проверяются доступность аккаунта, актуальность ветки, отсутствие собственного ответа, лимиты и действующие разрешения.

   Если пользователь уже ответил вручную или исходный комментарий существенно изменился, отправка отменяется либо возвращается на проверку.

9. Коннектор отправляет ответ.

   Выполняется одна попытка публикации с записью времени и идентификатора действия.

10. Приложение проверяет результат.

    При успешной проверке сохраняются ссылка или идентификатор ответа и время публикации.

    Если результат неясен, действие получает статус «Результат неизвестен». Повторная отправка блокируется до выяснения результата.

**Результат:** комментарий обработан, а итог подтверждён либо явно отмечен как требующий проверки.

**Состояния действия**

`Обнаружено → Анализируется → Черновик → Ожидает подтверждения → Готово к отправке → Отправляется → Подтверждено`

Дополнительные состояния: «Без ответа», «Отложено», «Отменено», «Требуется участие», «Ошибка», «Результат неизвестен».

Автоматически разрешённое действие проходит те же проверки, пропуская ручное подтверждение. Сохраняется правило, на основании которого отправка была разрешена.

**Критерии приёмки**

- Один комментарий не получает повторный ответ из-за повторной проверки.
- При неопределённом результате приложение не отправляет текст повторно вслепую.
- Одобрение нельзя использовать для другого текста или аккаунта.
- Изменение ветки перед отправкой учитывается.
- Ручной ответ пользователя обнаруживается, когда площадка позволяет его прочитать.
- Недостаток контекста приводит к запросу участия или отказу от ответа.
- История объясняет, что было отправлено, куда и на каком основании.

**5. Создание самостоятельных публикаций**

Этот процесс дополняет три основных сценария.

AI предлагает тему и конкретный канал, объясняет уместность и создаёт черновик с доступными материалами продукта. Пользователь редактирует его, выбирает время и подтверждает публикацию.

Для первой версии новые самостоятельные публикации требуют подтверждения. Отправка использует общие проверки аккаунта, лимитов, актуальности текста и результата.

Поддерживаются текст, ссылки и изображения там, где коннектор подтверждает эти возможности. Производство и монтаж видео относятся к последующему расширению.

**7. Техническая архитектура**

Предлагаемый стек первой версии: Electron, TypeScript, React и SQLite. Окончательный выбор браузерной реализации подтверждается прототипом с реальными сайтами.

| Компонент | Ответственность |
|---|---|
| Интерфейс | Карточки, формы, чат, просмотр результатов |
| Ядро приложения | Состояние продуктов, каналов и действий |
| Планировщик | Расписания и очередь задач |
| Адаптер AI | Запуск Codex или Claude, события, отмена, результаты |
| Сервис браузера | Профили, вкладки, управление и передача пользователю |
| Коннекторы | Получение данных и выполнение поддерживаемых действий |
| Проверка разрешений | Допуск действий, лимиты и подтверждения |
| Аналитика | Снимки показателей, переходы и результаты |
| Хранилище | Данные, история и версии |

AI получает только инструменты и данные, необходимые для текущей задачи. Ограничения на отправку применяются приложением, включая браузерные действия; они не должны зависеть только от текста инструкции модели.

Выполнение задач изолируется от интерфейса. Сбой AI-процесса не должен закрывать приложение.
