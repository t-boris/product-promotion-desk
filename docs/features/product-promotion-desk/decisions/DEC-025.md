## Context

On 2026-11-14 the AI account mission filled the whole Facebook registration form in the account's built-in browser (a hidden Electron WebContentsView, user agent cleaned of the Electron token) and pressed Submit twice. Facebook answered "An error occurred during your registration. Please try again." (the same silence as the owner's report after 0.3.4; the 0.3.5 check had Submit blocked, so this was the first real Submit). The cause is not proven: the browser may not be trusted, the "+" alias e-mail, the IP or the new profile after repeated tries, or automation itself. The owner asked to drive Chrome instead ("ВПЕРЕД"). The seam already exists: `RawPage` (src/core/browser-session.ts) and `BrowserService` (src/core/ports.ts); ControlledSession, the send ticket, the host check and the step vocabulary live in the core and do not depend on Electron.

## Alternatives

1. Give Claude Code the Chrome extension (`--chrome`): quickest, but the browser leaves the application's checks (no ticket, no deny-list, the owner's personal logins in the same profile); contradicts DEC-008 and DEC-024.
2. A thin own CDP client over the debugging pipe: no new dependency, but about 400 lines of input, navigation and upload code to own and test.
3. One app-wide switch between the built-in browser and Chrome: an existing account's session lives in one browser only, so switching would log every Reddit account out.
4. A per-account choice stored in the accounts table with a screen to set it: right in the end, but a new schema column and a new control that needs its own layout; the platform list does the job now and can grow into it.
5. Fingerprint tuning so that the built-in browser looks like Chrome: not done; the aim is a normal browser, not hiding automation.

## Decision

A second browser service, `ChromeBrowserService`, drives the installed Google Chrome (never a bundled or downloaded browser) for the platforms listed in `CHROME_PLATFORMS` (now: facebook), through `puppeteer-core` (pinned, no browser download) over a debugging pipe, one profile folder under the app's data directory for each account. A `RoutingBrowserService` picks the service for each account by its platform; everything else (Reddit and any other platform) stays in the built-in browser. The AI still reaches the browser only through the application's tools (`pageStep`, `read`, `goto`); the core keeps ControlledSession, the send ticket, the host check and the stop-the-AI on takeover. The page step logic (host check, real mouse click, real typing, drop-downs, upload) is shared by both back ends, not copied. Chrome is launched as a normal browser with a dedicated profile and no automation banner flags; the app adds no scripts or patches that change what the page can see about the browser (no fingerprint tuning). When Chrome is not found the account falls back to the built-in browser and the log says so. The owner's own window is the same Chrome window: taking control stops the AI, "Done" gives it back. `PPD_BROWSER=app|chrome` overrides the choice for probes. Deleting an account closes its Chrome and removes its profile folder.

## Reason

It fixes the one thing the app can fix without guessing: whether the browser is the reason. A real Chrome with a real profile is a browser every site supports, and the owner can finish a step by hand in it (Submit, CAPTCHA, a code). Going through the existing seam keeps every rule of the core (send ticket, takeover, hosts) in force, which handing Claude Code the Chrome extension would not: that would take the browser out of the app's checks and mix the owner's personal logins into the AI's reach (DEC-008, DEC-024). puppeteer-core is a pinned, Apache-2.0 library with 25 packages and no postinstall download; a hand-written client over the same pipe would be 400 lines of input and navigation code to own. If Facebook's refusal is about the e-mail or the IP, or about automation as such, Chrome will not change it; then the owner finishes the step by hand in the same window.

## Consequences

New dependency `puppeteer-core` (25 packages, 32 MB unpacked). A Chrome window appears on screen for a Facebook account (it is the AI's window and the owner's window at once). A Chrome profile is separate from the built-in partition: an account moved between back ends has to sign in again (no existing Facebook account holds a session). The built-in browser stays the default for every other platform. Version 0.13.0. Not proven: that Facebook accepts the registration in Chrome; the owner tries it at the keyboard.
