## Context

Section 4 of docs/design/remaining-work.md asked whether an account should support both API and browser modes at once (e.g., Threads or Facebook reading via browser while posting via API) or keep one access mode per account.

## Alternatives

1. Allow one account to hold both a browser session and an API key and switch between them or fall back automatically.

## Decision

Keep one access mode per account: each account works either through its browser session or through the platform API, never both at once.

## Reason

Owner confirmed on 2026-11-28 to leave accounts as single-mode (either API or browser) to avoid dual-mode complexity.

## Consequences

No dual-mode account schema, UI switcher, or hybrid session/token coordination is built. Section 4 of docs/design/remaining-work.md is closed as decided.
