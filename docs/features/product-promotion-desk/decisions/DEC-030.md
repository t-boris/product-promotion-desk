## Context

Until 0.15.0 a post was a four-line text box and a typed absolute file path. Nothing could hold a picture as part of a post, a long post had no formatting, and the owner could not see how a platform would show it. The owner asked (2026-11-15) for pictures as a principal part of a post (choose, paste, or have the AI make one from a description the owner edits), long posts with formatting and pictures inside the text, and, mid-slice, for the post to be shown as EACH channel shows it, and for unsent posts to be editable and deletable.

## Alternatives

1. A rich-text editor library (rejected by the owner: no new library)
2. Pictures referenced by their original path (an approved file could change behind the approval)
3. Hash every draft with a markup field (would invalidate every earlier approval)
4. A different renderer for preview and for sending (they could drift: what the owner saw would not be what is sent)
5. Hard-delete of a deleted post's rows (the approval and draft rows are the audit trail; left to the owner to decide)

## Decision

(1) Pictures live in a per-product library (table media, files under the data folder, never changed after they are added); every draft attachment is a library picture, a path given by the API is copied in at once, so what was approved cannot change behind the approval. (2) A draft has markup legacy or markdown. The approval hash binds markup only when it is markdown (an unset key is left out of the JSON), so every earlier approval hash is byte-identical; a golden hash is pinned in a test. Legacy drafts are sent exactly as written. (3) A markdown draft is turned into what a platform shows by ONE function (renderForPlatform) that feeds the preview, the disclosure check, the approval-fit check and the request to the connector; Reddit gets Markdown, every other platform plain words, a title a platform has no place for is dropped and said so. (4) Approval of a markdown post is refused in words when the platform cannot show it or this application cannot send it yet (pictures go out only as a Reddit post by itself until slice B); the way out is to publish by hand. (5) The AI makes pictures from a description the owner writes or edits first (the AI proposes a start through the shared assist field), through the Codex image tool, one new picture per press, shared with the profile picture. (6) Own Markdown editor, no new library; the preview is built as React nodes from a parsed AST, never as HTML. (7) Each platform has its own sketch (Reddit, Instagram, feed, short post, message) and the owner can look at the post as any platform. (8) An unsent post can be edited in every state and deleted; delete is a reject that is final: no edit, deferral or approval brings it back, and its pictures are released.

## Reason

It is the smallest change that makes pictures and formatting real without touching the approval trail: no existing hash moves, one function decides what is shown and sent, and the core stays free of Electron (a MediaTools port, thumbnails as data URLs under the existing CSP). A sketch per platform answers the owner's need to see the result before approving.

## Consequences

Sending pictures to any platform other than Reddit (as a post by itself) is not possible until 0.17.0; the app says so at approval. A picture library needs a clean-up rule: pictures no live draft carries are removed after 30 days. Deleted posts stay as rows in a Deleted list. A permanent purge of deleted posts is not built and is an open question for the owner.
