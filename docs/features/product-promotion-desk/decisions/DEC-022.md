## Context

The design audit of 0.7.4 (BUG-011 and its 25 children BUG-012 … BUG-036) found an admin-panel look: no design tokens for space, motion, elevation or focus; several filled buttons per screen; red used for states that are not failures; text under 13px; spacing off any grid; no visible way through the launch of a product. QA run 20261114-070211-163d (BUG-037) asked for the same things on real data.

## Alternatives

1. Launch path counts in the core (a new field on Product or a new method): rejected by the owner in favour of the renderer, no API change
2. Edit a source by removing and adding it again: rejected, it changes the id and drops the statements' citations
3. Rename the old tokens everywhere at once: rejected, the alias layer keeps the change reviewable and leaves the inline styles working

## Decision

The interface follows ten principles carried by one token layer in src/renderer/src/styles.css: surfaces surface-0..3, text-1..3, accent with accent-tint and accent-on-tint, focus, success / attention / error / info each with a background and an on-colour, space-1..7 on a 4px grid, radius-sm..pill, shadow-pop, focus-ring, dur-fast / dur-base with ease-out (0ms under Reduce motion), and a type scale 13/14/16/19/24/32. The old token names stay as aliases. One filled button per screen (helpers use the accent-outline `secondary` variant); red only for failures, amber for "decide or fix", neutral for the owner's own choices; every interactive element has the same visible focus ring. The launch path Product → Passport → Goal → Channel → Publication is shown under the product header, as five dots on each product card and on the first run of Attention; its counts are computed in the renderer from channels.list and opportunities.list, with no API change. A source can be corrected in place through the new core method sources.update (same checks as sources.add; id and date kept; mirrors of the product's website and description refused).

## Reason

The owner asked for the whole concept to be built in one batch, approved sources.update and the renderer-side counts, and asked for delivery to the end as 0.8.0. Tokens with aliases change the look without rewriting every page, and keep the texts and test ids the QA scenario reads.

## Consequences

New screens use the tokens and the one-main-action rule; a second filled button needs a reason. The launch path reads 'approved publication' as one in the ready, sending or confirmed state, counting standalone publications only. sources.update is part of the RPC contract (IPC and web mode carry it generically).
