## Context

B1 (2026-11-14) restricted the post mission to the MCP toolbox and refused Codex there, because Codex has no switch that removes its shell and file tools: an engine with full access can be prompt-injected by page text and act around the send ticket (the ticket is a boundary only on the MCP path). DEC-024 and DEC-042 say publishing and watching work with Claude Code only. A Codex owner could not send, watch or search trends in the AI browser at all.

## Alternatives

1. Keep the refusal and let the owner switch the engine to Claude Code in Settings (the safe option; the owner declined it)
2. Run a browser task with Claude Code automatically while Codex stays the writing engine (kept the confinement; the owner declined it)

## Decision

The application no longer refuses a browser mission (post, join, watch, trend search) because the selected engine cannot be held to the application's MCP tools alone. Any selected engine that can run an agent (Claude Code, Codex) may do it. An engine that can be held to the tools (Claude Code) still is: `confined`. Every mission that publishes or reads pages of strangers is also `quiet` for every engine: nothing the engine or the system printed goes into an error message. What the send needs does not change: the send ticket, the approved content checked against the page, the owner's own press, no scheduled or automatic send by the AI browser. The only engine refusal left is an engine that cannot run an agent at all (`engine_cannot_drive`). The Settings hint says that Codex cannot be held to the tools and could also run commands and read files on the Mac.

## Reason

The owner, 2026-11-20, after Codex was refused at sending to Instagram/Threads/Facebook: "Let Codex publish" and "Any selected AI agent could be used". The owner chose to have one engine for everything over the confinement of the post mission.

## Consequences

A prompt-injected page can steer Codex while it works the browser: Codex can run commands and read files on the Mac, outside the send ticket. This risk was accepted by the owner and is not removed by the application; Claude Code remains the engine that is held to the tools, and a quiet run keeps page text out of error messages and the log for both. Real publishing with Codex on Instagram, Threads and Facebook is unproven. The adapter still refuses a `confined` run for Codex, so confinement is never claimed for an engine that cannot give it.
