## Context

Until now every account was a browser session and every connector worked inside the account's signed-in page. The owner's goal of 2026-11-27 (docs/design/publishing-api-and-schedule-plan.md, phases D and E) asks for posts, comments and replies through a platform's official API where one exists, so a scheduled post goes out without a browser and comments are read by the application itself. Telegram is first: a bot with a token.

## Alternatives

1. A switch on an existing browser account: one account would then have two identities and two send ways
2. Replace the Telegram browser preset with the bot connector: personal Telegram accounts and channels the owner does not administer would stop working
3. Store the key as the account's password: the automatic sign-in would type it into a web form

## Decision

An account has an access way: "browser" (as before) or "api". An API account is a separate account of the platform (for Telegram, the bot), holds one key in the vault under its own name (never the password entry, never shown to the AI), and its channels use the platform's API connector: they are read by the application (reads = true) and the connector carries every send, pictures and video included; the AI browser is not used for them. A connector that works through an API declares it (what the key is called and the steps to get it), is never chosen by an address alone, and reaches the network only through one HTTP port of the core and the key only through its own context. Existing browser accounts and their channels are not changed or moved.

## Reason

A bot is a different identity from the owner's personal Telegram login, so it is a different account, not a mode of the same one; this keeps "one send way per channel" true without moving anyone's existing channels. One port and one key entry are built once for every later API connector (Facebook Page, Threads, Instagram, X).

## Consequences

A new column on accounts (access), a vault entry per API account, an HTTP port in the core, and a table of the messages Telegram delivered (a bot cannot read a channel's history, only what arrives while it is connected; updates older than 24 hours that were never collected are lost, and a comment is read only where the channel has a linked discussion group that the bot is in). Unproven live until the owner creates a bot and pastes its token.
