## Context

0.3.5 added eyes (DEC-016). The owner then asked for the hands: after e-mail and password are saved, the AI opens the browser and fills every value, solving problems it sees. Verified on the real Facebook registration form with test values and the submit button blocked: the form filled in 4 rounds.

## Alternatives

1. A selector-writing engine (rejected: the engine could target anything)
2. A tool-using engine such as Codex driving the browser itself (rejected: it can act on this computer, so it is never shown a website)
3. Real mouse input only (rejected: the hidden agent tab drops it; showing the tab would change the architecture)

## Decision

The AI controls the account's browser as a person would, for any work that publishes nothing (signing up, signing in, looking around, setting up a profile). Each round: the application takes a snapshot of the page (every usable element labelled "e12", the visible messages, a visible human check), a tool-free engine answers with steps (type, select, click, key) naming labels, the application checks every step against the snapshot and carries it out through BrowserPage.pageStep, then looks again. pageStep is the second write-class operation without a SendTicket (the first is signIn): it refuses a page outside the task's hosts, works only on a labelled element, and publishes nothing. A task that can publish still goes through a connector with a ticket. Secrets are named to the engine ({{PASSWORD}}), never shown, typed only into a password field, never logged. Real mouse and keystrokes are used where the tab takes them; because the agent's hidden tab does not receive a real mouse press, delivery is checked and the page's own events are the fallback. A custom drop-down is chosen from in one step. The loop stops for a CAPTCHA or code, a page that does not react twice, a page outside the platform, the round limit, Stop, or the owner opening the window; after "done" the site's own login check decides.

## Reason

The owner wants the AI to do what a person does in the browser on every channel; the owner gives only the e-mail and password. MarkView's browser shows the approach works (snapshot with element refs, trusted input). Keeping the engine text-only and checking every step against the snapshot keeps REQ-004 intact.

## Consequences

The owner must select Claude Code (the only tool-free engine) for the agent to run. AI-chosen values are kept in the run state only; persisting them on the account is later work. A code sent to the e-mail still needs the owner until the mail reader exists.
