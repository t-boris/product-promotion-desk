## Context

DEC-082 left a PNG picture to the owner ("save it as JPEG"), because the core has no picture converter and a new library needs the owner's word. The plan's phase H says "JPEG only: other formats are converted before upload". Pictures made by the AI and screenshots are PNG, so most posts would have been refused. The main process already has a picture tool made with Electron's own image support and no library (ImageShrinker, used when a site refuses a profile picture for its size); it writes a JPEG.

## Alternatives

1. Leaving the conversion to the owner (DEC-082 as first written): most AI-made pictures are PNG
2. A picture library in the core: not needed, Electron's image support is already used for this

## Decision

The place for files takes an option "JPEG under N bytes": a picture that is not JPEG is put as a JPEG copy made by the existing ImageShrinker in a temporary folder that is deleted once the file is put; the original is never changed and the object is named after the picture with ".jpg". The Instagram API connector asks for it for every picture, with Instagram's 8 MB limit. Before the owner approves, only a picture that is neither JPEG nor PNG is named as a problem; a picture of which no copy can be made fails the send in words before anything is asked of Instagram. This changes the consequence of DEC-082 that a PNG must be saved as JPEG by the owner.

## Reason

It is what the approved plan says, it needs no new library, and it keeps the conversion in one place (the place for files) for any later platform that takes only JPEG.

## Consequences

Unproven with real pictures in this path: a PNG with transparent parts gets whatever background Electron's JPEG writer gives (expected black), and kinds other than PNG and JPEG (WebP, HEIC, GIF) are converted only if Electron reads them on this Mac; when it cannot, the send fails with the words "a JPEG copy of it could not be made". A JPEG over 8 MB is still sent as it is and refused by Instagram in its own words.
