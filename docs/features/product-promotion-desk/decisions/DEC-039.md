## Context

Phase E of docs/design/ui-redesign-plan.md (D4 of DEC-037: the Feed reads Reddit first). Until now only a new comment in one of the 25 newest discussions became an opportunity; new posts were stored and shown nowhere, and replies to the account and mentions were never read. This record covers the core (E1 model, E2 reading, E3 drafting); the Feed screen (E4) is separate. No live Reddit probe was made: the inbox is built on Reddit's documented listing shapes and proved with fakes and local fixtures only.

## Alternatives

1. A separate table for Feed items (rejected: approval, gate, one voice, sending, history and attention all read opportunities; a second object would need all of it twice, and the plan says an item needing a decision is the same object in Feed and Inbox).
2. A new post gets a placeholder comment row so that every consumer keeps working (rejected: it invents data the platform never had, and the gate would then compare a fake comment's hash).
3. Discriminate a post target by commentId being null (rejected: a comment-sourced row whose comment vanished also has a null commentId and must still cancel with comment_gone; the discriminator is source = new_post).
4. Read the inbox through the AI browser (rejected for the core: Reddit's inbox listing is a same-origin JSON read like the other reads; the browser stays for what the owner decides separately).
5. Let automatic mode answer a new post that looks like a thank-you or a plain question (rejected by the plan: auto never answers a new post; nobody wrote to the account).

## Decision

E1. Migration 307 adds opportunities.source ('comment' by default, so every old row is a comment), a unique index of one new_post opportunity per discussion, an index for the Feed's per-product listing, and channels.inbox_baseline_done_at. The type OpportunitySource = comment | new_post | reply_to_me | mention. opportunities.list gains the optional filters source and productId (additive). E2a. A discussion seen for the first time, not at the baseline, not written by any login of the product, not a post the app published, not locked or archived, while the account identity is known, becomes an opportunity of source new_post only when its title or text names one of the channel's topics or search queries (pure function matchesTopics: case-insensitive, whole word or phrase, Unicode-aware boundaries, regex-escaped terms, empty lists never match). Its target is the post: commentId null, discussionId set, destination the post address. An edited post sends its pending reply back to review. E2b. Connectors may implement readInbox(ctx, {limit}); the capability read_inbox says whether it works (unavailable with a fixed reason where the connector has none, set by the channel service; needs_check, verified or unavailable from the Reddit assessment). The monitor reads the inbox after the discussion read, signed-in only, in one batch of at most 25 items, reading at most 5 threads of unknown discussions for context with the 400 ms pacing. The first inbox read of a channel is its own baseline (stores, queues nothing). Items become reply_to_me or mention opportunities once per comment; own comments (any login, any confirmed result id) and a discussion another login already speaks in are handled as for every source. A failure, or the owner taking the browser, never breaks the discussion read; the reason is kept on the channel's read_inbox row. Reddit: two read-only GETs (/message/inbox.json and /message/mentions.json with mark=false), filtered to the channel's community. E3. reply_to_me and mention are drafted like a comment. For new_post the AI is told it is a new post by someone else, judges first whether an answer is worth giving (decision ignore with the reason ends it as no_reply), and the reply is a top-level comment. Sending a reply to a new post: the request's parent is the post (t3_), the destination is the post address, the content hash binds the draft to it; every guard stays (locked or archived, an own reply already under the post, an incomplete or unreadable thread, a changed post as the new post_changed block, one voice, approval bound to content, account and destination, reconciliation looks under the post). Auto never answers a new post, enforced three times: the eligibility check (modes.ts), the gate's automatic-approval branch (auto_rule_refused) and the existing refusal of an automatic send of an owner-approved reply.

## Reason

One object for every source keeps the safety rules (baseline, own-login exclusion, one voice, approval bound to exact content) in one place, so a new source cannot get around them. The post-target discriminator is the source, not a null comment, so the old cancel for a vanished comment is untouched. Defence in depth for auto-never-new-post and for idempotence costs little and each layer is proved by a test that fails when only that layer is removed (43 mutants of the safety rules were run, all killed). Reading the inbox as a signed-in same-origin JSON read follows how Reddit is read everywhere else and needs no new way of driving the browser.

## Consequences

Unproven until a live, owner-run check: the real shape and rate limits of /message/inbox.json and /message/mentions.json for a signed-in account (the connector falls back from missing fields to the context path and skips what it cannot place), whether mark=false really leaves the owner's unread badge alone, and whether mentions are listed in the inbox as well as in the mentions list. Limits to know: at most 25 inbox items per cycle, newest first, so more than 25 new replies between two cycles lose the oldest; every channel of the same account reads the account's inbox itself (N channels, N inbox reads per interval, filtered by community); a mention inside a post body (not a comment) is not found; an item the discussion read already queued as a plain comment is relabelled to reply_to_me or mention instead of being duplicated; a discussion first stored from an inbox item without a readable thread has an empty post body until the discussion read sees it; a first-seen post is queued whatever its age (no age cap yet). The renderer needs read_inbox in CAPABILITY_LABEL (Record of every key), and cards of a new post carry comment = null with the post as card.discussion.
