## Context

The publishing plan's phase J asks for Pinterest "publishing only". Pinterest's pages (read 2026-11-28) give an app a token of its own account with the client-credentials grant: POST /v5/oauth/token with the app id and the app secret key in a Basic header and a form-urlencoded body; the token lasts 30 days, acts "on behalf of the current app owner" and needs two-factor authentication on that account; no sign-in window and no redirect address are needed. POST /v5/pins takes a board's id, a title (100), a description (800), a link and one JPEG or PNG picture as base64. A board has an id and a name in the API and no address. There is no API for comments. GET /v5/pins/{id}/analytics gives the impressions of a period (at most 90 days back) and the lifetime numbers of reactions and comments. With Trial access a pin the app creates is seen only by its creator; Standard access is asked for with a video recording. A video needs the media upload, which is not offered with this grant. An app registered after 14 September 2026 reads boards and pins only of a business account.

## Alternatives

1. The authorization-code flow with a redirect address and a refresh token: needs a listener for the redirect and serves other people's accounts, which the application does not need
2. Keeping the 30-day token pasted by the owner: it would end every month and Pinterest shows no page that makes one
3. The profile as the channel with the board chosen in a setting: a new setting and a new screen part for what the address already says
4. Marking the channel as read by the application because its own pins can be listed: the screens would promise a feed that never fills, since there are no comments

## Decision

A Pinterest account "Through a developer app" keeps two values together in the vault: the app id and the app secret key. The key form has a second required field for it (a general ApiAccess.keyId: a value beside the key that is no secret and is kept with the key). On save the pair is checked by asking Pinterest for a token. The application asks for a token itself whenever it needs one (kept in memory only, asked again when it has a day left or Pinterest stops taking it), so nothing ends for the owner and nothing is renewed by hand. A channel is the address of a board of that account (pinterest.com/name/board); the board is found among the account's boards by its name written the way an address is, and the owner is told in words when the account is another, the board is not listed or two boards read the same. A pin is one JPEG or PNG picture up to 20 MB with a title, a description and a link, sent from the local file. A video, more than one picture, a GIF and a reply are refused before Pinterest is asked; the video is also named before the approval. The channel is for the owner's own pins: not read, not monitored, never watched in a browser (as the LinkedIn API channel). Under each pin the application reads reactions, comments and the impressions of the last 90 days. A lost answer is resolved by looking among the account's newest pins for the same board, title and description. The network port takes a form-urlencoded body. The Add-a-channel form and the refusal of an address show the example and the hint of the API connector when the chosen account works through the API (for Pinterest a board, not the profile).

## Reason

The client-credentials grant is the only way of Pinterest's API that needs neither a sign-in window nor a redirect address, and it serves exactly the owner's case: their own account posts to its own boards. Keeping the pair instead of a token removes the 30-day end from the owner's sight. A pin lives on a board, and the API names boards only by id and name, so the board's address is the channel and its name is the link between the two. Publishing only is what the plan asks and what the API allows: it has no comments.

## Consequences

Built on Pinterest's documentation and a fake server; unproven with a real app: the token request, the exact refusals (two-factor authentication, Trial access, a personal account), the match of a board's name to its address for names with unusual characters, a secret board in the list, the analytics answer. Until Pinterest grants Standard access the pins are seen only by the owner; the steps and the channel's abilities say so. Not built: a video pin, several pictures in one pin, board sections, alt text, the account's followers and monthly views in Results (a channel that is not read shows no account numbers there), comments (no API; the open question of one account with both a browser sign-in and a key covers them).
