## Context

Until now the application promised not to read the account window at all. In practice a site can refuse something without any visible sign (a Facebook registration form that spins and returns), and neither the owner nor the AI could see why. The owner asked that the application see the page the way a person with the developer tools open does, so that it can explain and later resolve such problems itself.

## Alternatives

1. Keep the window unobserved and ask the owner for screenshots (rejected by the owner)
2. Capture screenshots and page text continuously while the window is open (rejected: it would record what the owner types, including a password shown with the eye icon)
3. Open a remote debugging port on the app (rejected: any local process could then drive every signed-in session)

## Decision

The application watches the network metadata and the console of an account's page all the time (host, path, method and status of requests that were sent or refused; console errors; never a query string, header, cookie or body) and logs a refusal by the site as one throttled line. It runs a script in the owner's window and takes a screenshot only when the owner asks ("What does the page show?"). What it reads is what a person can read (text, alerts); the value of a form field is never read, so a typed password cannot appear in a report. Reports are kept as local files in the data folder (the newest six per account) and go with the account. Clicking and typing in the owner's window stays forbidden while the owner holds control (REQ-004).

## Reason

The owner's remark of 2026-11-08: the browser is the main function, the application should see what happens in it like a person with the debug window open. Network metadata and console are not the page's content, so they can be watched safely all the time; reading the text and taking a screenshot are done on request, which keeps the existing promise that nothing runs in the owner's window by itself.

## Consequences

The AI sign-up assistant (REQ-015) has eyes: it can read the page and the network and react to what it sees. A report may contain what the owner typed in ordinary fields (a name, an address) as a screenshot, so it is stored only locally and only on request. The log shows when a site refused something.
