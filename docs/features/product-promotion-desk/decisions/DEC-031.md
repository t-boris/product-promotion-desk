## Context

Until 0.16.0 nothing could publish a post with pictures except Reddit's one picture by itself (connector), and nothing could publish to Instagram, Facebook or Threads at all: the universal connector refuses attachments and has no bundled flow. The post mission of the AI browser (B1, DEC-013 and the B1 owner decisions) typed plain text and refused drafts with attachments; DEC-013 excluded uploading photos from the application. The owner decided (2026-11-15) that pictures and the other platforms go through the AI driving the account's own browser, in the existing confined post mission (Claude Code only, ticket-bound), extended with file upload.

## Alternatives

1. A bundled connector flow per platform (Instagram, Facebook, Threads): each is a scripted site flow that breaks when the site changes, and the app could not prove any of them without the real sites
2. Official platform APIs: need app review, business accounts and tokens per platform; out of reach for the owner's own accounts
3. Let the AI type or upload anything the page asks for: the mission would no longer be bound to the approved content
4. Scheduled sends through the AI browser: an unattended browser driven by an AI, left as a separate decision

## Decision

(1) The approved content of a post mission carries the approved pictures: each by a name the application chose (picture-1.png, in the order of the post; never the owner's file name), the path the AI never sees, and the hash the approval was bound to. (2) A new tool browser_attach({ref}) puts ALL the approved pictures into one file input listed as input:file, in ONE step (an input holds the files of its last step, so pictures put in one by one would replace one another): only into an element the AI was shown and that is still what it was, only on the approved page of the platform (for a community, its submit page), only while no form holds text, only if every file on disk still hashes to what was approved, and once per document. The AI names no file and no path. After the step the application reads back what the input holds (count and sizes must be the approved files; an input the site emptied because it has read the files is taken at its word). "The pictures are in the form" is not a history of calls: it is a record of the document (performance.timeOrigin) they went into, and is true only while that document is the page, so a page loaded again has an empty form and the pictures must go in again; the form of the input, where the page marks forms, must be the form of the fields and of the control. (3) browser_submit is refused until the approved pictures are in the form of this document, reads every file from disk once more before the press, and a post of pictures only is a post; the caption is typed and the control pressed by the application under the ticket, exactly as for text. (4) From the first picture in the form the AI's own clicks are those that go on to a next step (a control named Next or Continue, whole name) and nothing else; choices in lists are refused; the control that publishes (now including Share and the Russian forms) stays browser_submit's alone. (5) A click that opens the system's file chooser (a file input, or a button named like Select from computer) is never made: nobody can answer that window; the picture goes in by browser_attach. (6) For a new post on a platform whose compose form is a dialog over its own pages (a closed list: Instagram, Facebook, Threads), the front page of the platform's site is a place of the post too; no other page, and a destination that is only the root of a site means the root and nothing under it. "Share" is a publishing name only there; on any other platform, and under a comment, it shares the page and is refused. (7) Who sends: the AI browser carries a send only when the owner chose it in Settings (new Publishing switch), the engine can drive it, the send is the owner's own press on an approval the owner gave themselves; a scheduled send or an automatic approval never drives a browser, and the refusal says so (press Send yourself, or copy the post). With pictures it carries only what the connector cannot (Reddit's one picture by itself stays on the connector). One function (sendWays) answers this for the approval's fit check, the gate's re-check at the send and the choice of executor, so what the owner is told can be sent is what is sent. (8) Pictures are sent beside the text, in order; a picture placed inside a long Reddit text is typed as the words with the pictures attached, not as an inline mark (the real editor behaviour is unproven).

## Reason

The mission stays the one boundary: the tool layer decides, the ticket binds the exact content, and the brief per platform is a courtesy, not a barrier. Everything the AI could do wrong with a file is refused by name, by role, by page, by state or by hash, and what is not recognised is left to the owner (needs_owner), never guessed. It is the only way to reach Instagram, Facebook and Threads without per-site scripts, and the one that lets the owner watch every step.

## Consequences

Unproven until the owner tries on the real sites: that Instagram, Facebook, Threads and Reddit's editor accept the file by their input in the way the local pages do, how they name their controls (Next, Share, Post), that Claude Code drives the wizard to the caption step, and that the rich-text boxes of these sites hold the typed caption so the read-back accepts it (it refuses, and nothing is published, when it does not). Proven here on local pages in real Chrome (real input events, files byte for byte) and in Electron. DEC-013's exclusion of photo upload is lifted for the post mission only. Scheduled sends of a post with pictures stay refused with a reason; making AI-browser sends unattended is a separate decision.
