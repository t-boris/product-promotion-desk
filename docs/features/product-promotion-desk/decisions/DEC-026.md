## Context

DEC-025 chose the browser by platform (Facebook in Chrome). On 2026-11-14 the owner widened it: "they can work in both places"; "we choose which browser to work with, internal or external"; "by default it is Internal"; "it must work properly in both". The session of an account (cookies, storage) lives in one browser's profile: Electron's partition or a Chrome profile folder under the data dir. Two sessions of one account at once, or a hidden page of one browser left behind while the other works, would be two controllers of one account.

## Alternatives

1. Keep the platform list and add an override: cannot say 'this Facebook account in Internal, that one in Chrome', and the owner asked for the choice.
2. A choice at the start of each operation: the cookies are in one browser, so an operation in the other would find a signed-out account every time.
3. An app-wide switch: moving it would sign every account out.

## Decision

Account.browser is `internal` (default) or `chrome`, stored on the account, set in the account's own screen (accounts.setBrowser) and in effect for every operation on that account (sign-up, sign-in, profile, opening the window, publishing). RoutingBrowserService reads the setting at each call; the platform list (CHROME_PLATFORMS) and the silent fallback are gone. PPD_BROWSER=internal|chrome still forces one for every account (probes, support). Choosing Chrome is refused when Chrome is not installed, and a Chrome that went missing later is said in plain words on use, never replaced by the other browser. Switching is refused while the AI works on the account or the owner holds its browser; on a switch the previous browser's page and window are released (Chrome is closed, its profile is kept), so there is exactly one live browser for an account. The other browser's session stays where it was made: switching back finds it, switching forward means signing in again in the new one, and the screen says so before the switch.

## Reason

The owner decides which browser an account lives in; the app has no way to know which one a site accepts. One account, one live browser, keeps the rules of the core (one controller of a session, the takeover, the send ticket) true without any change. A stored per-account choice is what DEC-025 had listed as the right end state (alternative 4); the owner asked for it now.

## Consequences

New column accounts.browser (default internal); the Account type, the API (accounts.setBrowser) and the account screen get a Browser block; BrowserState says whether Chrome is installed; RoutingBrowserService calls releaseAccount on the previous browser at a switch. DEC-025 stays in force for how Chrome is driven; only its choice by platform is replaced by this decision.
