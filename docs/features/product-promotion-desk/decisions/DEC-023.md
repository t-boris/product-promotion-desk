## Context

On 2026-11-14 the owner asked for the interface to look like a very neat, expensive macOS application. The baseline of 0.8.0 (docs/design/macos/baseline, measured on an own instance) still reads as a web admin panel: a solid text-only sidebar with a full-width "Hide menu" button, a web top bar of coloured pills, body text at 14px with five sizes in use, 36px controls, underline tabs, bordered cards inside bordered cards, dashed disabled buttons and empty states, and up to five filled buttons on one screen (Channels tab). At 980x640 the product tabs end at about y=560px and the product list turns into horizontal cards with the website broken inside a word.

## Alternatives

1. Keep the DEC-022 look and only tidy spacing: rejected, it does not reach a native macOS feel (sidebar, title band, controls and tabs stay web-like)
2. Imitate the macOS 26 Liquid Glass material in CSS (blur, highlights): rejected, it reads as fake inside a web view; the real material comes from the window's vibrancy
3. Use an icon library (lucide or similar): rejected, a new dependency for about twenty glyphs; local SVG glyphs drawn in the SF Symbols manner instead
4. Move the page title into the toolbar band: rejected, long subtitles would be cut at 980px; the page keeps a 22px large title in the content and the toolbar keeps the status
5. Follow the system accent colour: rejected, the owner's Mac uses Multicolor, where each app shows its own accent; the app keeps an indigo accent, now the system indigo and used sparingly

## Decision

The interface follows docs/design/macos/visual-system.md. The window keeps titleBarStyle hiddenInset, gets vibrancy 'sidebar' with a transparent window colour and the window buttons centred on a 52px band; the renderer marks html[data-chrome] native or web, and the sidebar is opaque in web mode and under Reduce transparency. The sidebar shows one 16px local SVG icon per entry, the section header "Promotion Desk", Log and Settings pinned to the bottom, and the toggle ("Hide menu" / "Menu · N") as an icon button in the band. The toolbar band holds the version, AI engine and Accounts status on the leading side and the automation state and toggle on the trailing side, never a filled button. DEC-022 token names stay with new values (neutral macOS surfaces, system indigo #5856d6 / #5e5ce6, darker light success and attention for 4.5:1) plus new tokens (sidebar, field, field-border, bezel, selection, press-fill, segment-track/thumb, control and thumb shadows, gutter 20px, toolbar-h 52px, sidebar-w 224px, row-h 28px). Type scale 13/15/17/22/26 with body 13px and nothing under 13px. Every control 28px with radius 8. All tabs become a segmented control with a raised neutral thumb. Content uses group boxes on a neutral page, list panels with tinted selection, zebra tables, frameless empty states, macOS menus with an accent highlight and a sheet for the agent question. One filled button per screen, chosen as the next step (§10 of the spec); page-header create actions become bezel buttons with a plus glyph. No visible text, accessible name, role or test id changes.

## Reason

It matches what the owner asked for with the means the app already has (Electron window options, CSS tokens, local SVG), keeps the DEC-022 principles and the QA-bound texts, and fixes the measured defects of 0.8.0: the mock built only from the new tokens, captured in a real window, has no toolbar overlap, one-row launch path and tabs ending at y=292px at 980x640, and only 13/15/17/22px text.

## Consequences

The main process window options change (vibrancy, transparent background, trafficLightPosition y 19). The dark window colour changes from #121418 to #1e1e20; the QA scenario check c19 that names #14161a describes an older value. Verification uses requirements V-01 … V-24 of the spec with scripts/design/tour.mjs and native.mjs on the packaged build. Review lists (Attention, Opportunities, Publications) mark only the first card's main action as filled; the same action on later cards uses the secondary variant.
