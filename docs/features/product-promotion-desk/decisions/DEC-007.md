## Context

The project had no versioning rule, no CI workflow, no deployment procedure and no GitHub issues, although delivery of this feature requires all four.

## Alternatives

1. Same setup with a single umbrella GitHub issue instead of eight.

## Decision

Version with SemVer in package.json, starting at 0.1.0 for this feature, and tag v0.1.0 after merge. CI is GitHub Actions on macos-latest running typecheck, lint, tests and build. Deploy is an unsigned arm64 .app built with electron-builder and installed into /Applications on the owner's Mac, verified through the bundle version and Settings > About. File eight GitHub issues, one per plan item I-1..I-8, link them to the feature, and close each when its work is merged.

## Reason

The owner approved the proposed setup. It creates nothing outward-facing beyond issues, a pull request and a tag in the owner's own repository.

## Consequences

Later changes bump the version by SemVer (minor for features, patch for fixes while below 1.0). Signing and notarization are outside version 1 and need a separate decision. The CI workflow is part of this change and must be green before merge.
