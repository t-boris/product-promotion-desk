## Context

The plan's phase I says "post with media from local files"; 0.87.0 built pictures and a GIF and left a video to X itself. X's guide "Chunked Media Upload" (read 2026-11-28): `POST /2/media/upload/initialize` (JSON: media_type, total_bytes, media_category `tweet_video`), `POST /2/media/upload/{id}/append` (multipart: segment_index from 0, media; a segment of 5 MB at most is asked for), `POST /2/media/upload/{id}/finalize`, and while `processing_info` is returned `GET /2/media/upload?command=STATUS&media_id=…` after `check_after_secs`, until `succeeded` or `failed`; then `POST /2/tweets` with the media id. The reference lists `video/mp4` and `video/quicktime`. A post holds up to 4 pictures, one GIF or one video. How long a video may be depends on the account (20 minutes and 8 GB without X Premium), and X checks it again when the post is made. X's price list has no row for an upload.

## Alternatives

1. Keep a video for X itself: the plan's item stays partly unbuilt
2. Read the whole file into memory and cut it there: a video of several GB would not fit
3. Check the video's length before sending: the application would need a video reader for what X says itself

## Decision

A post or an answer on X through the API may carry one MP4 or MOV video with no picture beside it. The connector starts the upload with the file's kind and size, sends the file in segments of 4 MB read straight from the file (the network port sends a named part of a file, so a large video is never held in memory whole), closes the upload, and asks about the processing when X says to (never sooner than a second, never later than half a minute) for at most ten minutes; only then the post is made. Whatever stops before the post is a failure with "Nothing was sent" (an uploaded video that is not attached is seen by nobody); the post itself keeps its "not known" outcome for a lost answer. The preview says before the approval that pictures and a video do not go together; the line "A video is not sent to X through its API" is gone. The length of a video is not checked here: X's refusal at the post is said in X's words.

## Reason

The plan asks for media from local files and every request is in X's documentation. Segments read from the file keep memory flat for a file of any size X takes.

## Consequences

The network port's file of a form may name a part (start, end). Unproven with a real paid X app: the upload itself, the processing time, X's refusal for a too long video. Not built: a video's cover or subtitles on X (not in the plan).
