## Context

Reported 2026-11-15 with a screenshot: an Instagram channel (www.instagram.com/boris_chart_notebook) stayed in "Setting up" with "Baseline: Reading the channel failed: There is no site profile for this site yet, so nothing can be read or sent automatically." Activating a channel meant a first read of its discussions (the baseline). The universal connector, which serves every platform that has no connector of its own (Instagram, Facebook, Threads, X), reads only a site it has a validated site profile for, and none exists. The gate and the post groups refuse every send from a channel that is still in setup, so such a channel could never post either, although DEC-031 made the AI browser able to publish there. The failure also repeated on every scheduler cycle.

## Alternatives

1. Make the baseline optional for every channel: a Reddit channel without its first read would then treat every old comment as new, which is the exact thing the baseline prevents
2. Write a site profile for Instagram, Facebook and Threads so the app can read them: unproven against the real sites, fragile against their layout changes, and it would not help the owner who only wants to post
3. Let the channel stay in setup and allow sends from setup: the status would lie (a channel that sends is not 'setting up') and the gate's rule would have an exception that every other path must remember
4. A separate kind of channel in the data model: a second table and a second set of screens for something that differs from a normal channel in one answer (can the app read it)

## Decision

(1) A connector may say whether it reads a channel at all (readsChannel, optional; absent means it does). The universal connector reads a site only when a valid site profile exists for its host. (2) The channel keeps the answer (channels.reads, migration 306, default 1) and it is asked again when the channel is connected, assessed and activated, and at every start, so an older channel and a channel whose site profile was added or removed are corrected without re-adding. (3) A channel the app does not read is activated without a first read: it needs a signed-in account and a posting ability that is not known to be impossible, and becomes active with the status line "Your own posts only." The monitor, the scheduler, the metrics sweep and "Check now" leave it alone (no failure loop, no Next check); resuming it goes back to active, not to setup; no reply is prepared for it and no mode is chosen (the mode card is one line). The content mix keeps working there: observe is not a block on a channel that has no replies. (4) Its capabilities say it plainly: reading, replying, rules, metrics and membership are unavailable ("the app does not read this site"), publish_post and verify_send stay needs_check and are confirmed only by the first real post. (5) Posts go through the same approval, gate and AI-browser send on the owner's press as on any channel. (6) A channel on a platform of one handle is called by it ("@boris_chart_notebook"), not by host and path; the destination of a post stays the channel's address, so no approval moves. Reddit and any site with a valid site profile are unchanged.

## Reason

The owner connects Instagram, Facebook and Threads to post on them; reading them was never required for that, and the first read was the only thing standing between the channel and its first post. The question "does this apply here" belongs to the connector at the moment of the press, not to a stored string or to an error shown after every retry. Keeping the answer as one flag on the same channel keeps the architecture: one entity per screen, one approval path, one gate.

## Consequences

New: migration 306 (channels.reads), Connector.readsChannel, readableChannels in the scheduler, reconcileChannels at start, handleOf in the platform presets, own-posts words in the renderer. A channel is read only when its connector has a valid site profile whose channel pages include the channel's address: a profile written for the groups of a site says nothing about a page of the same site, so that page is a channel for own posts too (found by the independent review). The capability table of an Instagram channel now shows the reading rows as "Unavailable" with the reason told once, instead of nine rows as "Needs verification". A channel that is later given a valid site profile is read from the next start or the next assessment on: it is active with no baseline, so the monitor's first cycle stores what exists as the baseline and creates no opportunities (the same rule as for any first read); an assessment decides from the answer it has just been given, not the stored one.

From the independent review, all fixed with a test and a mutant each: the owner-pressed metrics refresh, "Refresh all" on Results and the per-channel Refresh no longer touch a channel the app does not read (no run is recorded, so none fails, and the other channels are still refreshed); a channel the scheduler suspended and later restored keeps no "Next check" and says again "Your own posts only."; the start-up sign-in check also covers an account whose only channel is for own posts (it sends whatever its mode); a channel in setup cannot be paused and "Resume" never leaves setup, so neither is a way round Activate and its checks of the account and of posting; a name is never made from a page of the platform itself (explore, home, search, marketplace, the web app of Telegram); a site profile's {{target}} stays the address the connector stored (host and path), whatever the channel is called.

What the owner will meet, and what is not proven: the app cannot read these platforms, so it cannot read a post back. After the AI presses Send the result is "unknown" (existing DEC-031 rule: the app's own finding, never the AI's word) and the owner tells the app whether the post is up, with its link; the card says so in plain words. Posting therefore stays "Needs verification" on such a channel: nothing in the app can verify it, and the capability text says that instead of promising confirmation by the first real post. Unproven until the owner tries: that the AI browser really publishes on Instagram, Facebook and Threads (DEC-031). Open question for the owner: whether to accept, for a channel the app cannot read, a different evidence than the owner's own word (for example the AI's report with a screenshot of the published page); it would change DEC-031's rule that the application itself finds the text on the site, so it is not done without a decision. Not changed: how replies on those platforms could ever be read.
