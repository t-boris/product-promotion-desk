## Context

The owner said on 2026-11-08 (translated from Russian): the project is bootstrapping, so everything may go straight into main, no separate feature branches, all merges to main at once, CI need not be run or waited for, main is kept only for history, and the goal is to produce the installer and install it locally as fast as possible; and, not forgetting, every change from now on bumps the version. Records checked: DEC-007 (SemVer from 0.1.0, GitHub Actions, local deploy, one issue per plan item) and DEC-008 (one PR with a commit group per plan item, live Reddit acceptance with the owner after deploy).

## Alternatives

1. Keep a branch and a PR per change with green CI before merging (rejected: the owner wants speed while bootstrapping)
2. Bump the version only at releases (rejected: the owner wants a bump after every change)

## Decision

While the project is bootstrapping: commits and merges go directly to main and are pushed at once; no feature branches and no waiting for CI (the workflow may still run on push and is not a gate); every change merged to main bumps the version (patch by default, minor for a new capability) and gets a tag vX.Y.Z; the local installer is built and installed with npm run deploy:local and the installed version is checked against package.json. DEC-007 stays in force for versioning, local deploy and issues; DEC-008 stays in force for the live Reddit acceptance, which still needs the owner and explicit in-app approval for anything published.

## Reason

Speed to a locally installed build is the owner's priority at this stage, and a version number per change makes it clear which build is installed.

## Consequences

The rule of the original goal "never commit to main" and the CI-before-merge step no longer apply until the owner ends bootstrapping. Nothing weakens the product's own safety rules. README Versioning states the bump rule; tasks/lessons.md and the project memory carry it.
